Connect

Komplyt keeps what your AI knows as knowledge you own. It is an MCP server that works with Claude, ChatGPT, Cursor and any MCP client.

MCP server URL

https://kg.kompl.yt/mcp

  1. In Claude or ChatGPT, open the connector directory and add Komplyt. One click, no URL needed.
  2. In any other MCP client, add the server URL shown above (examples below).
  3. Sign in with your Komplyt account when prompted and approve access.

Claude Code

claude mcp add --transport http komplyt https://kg.kompl.yt/mcp

Cursor and other clients with a JSON config

{
  "mcpServers": {
    "komplyt": {
      "url": "https://kg.kompl.yt/mcp"
    }
  }
}

Quick Install

Client-specific steps. The command and JSON config are in Connect.

  1. 1. Open Settings → Connectors → Add custom connector
  2. 2. Enter URL: https://kg.kompl.yt/mcp
  3. 3. Leave OAuth client ID/secret empty (auto-registered)
  4. 4. Click Add, then Connect
  5. 5. Sign in with your Komplyt account and approve access
  6. 6. Enable the connector via the tools menu in chat

Run the claude mcp add command from Connect, then run /mcp in Claude Code to sign in with your Komplyt account and approve access.

Requires Developer mode (Plus/Pro/Team/Enterprise):

  1. 1. Enable: Settings → Apps & Connectors → Advanced → Developer mode
  2. 2. Click Create or "Add custom connector"
  3. 3. URL: https://kg.kompl.yt/mcp
  4. 4. Authentication: OAuth (auto-discovery)
  5. 5. Sign in with your Komplyt account and approve access

Add the JSON config from Connect to .cursor/mcp.json, then sign in with your Komplyt account when Cursor prompts.

Any MCP-compatible client can connect via HTTP transport:

Endpoint

https://kg.kompl.yt/mcp

Authentication

OAuth 2.1 with PKCE, discovered automatically. See Authentication.

Protocol

MCP Streamable HTTP (JSON-RPC 2.0)

Authentication

The server uses OAuth 2.1 with PKCE (S256) and dynamic client registration. MCP clients discover everything automatically. An unauthenticated request returns 401 with a WWW-Authenticate header that points to the resource metadata. Scopes: kg:read, kg:write.

  • Authorization server metadata (RFC 8414): https://www.kompl.yt/.well-known/oauth-authorization-server
  • Protected resource metadata (RFC 9728): https://kg.kompl.yt/.well-known/oauth-protected-resource

Tools

kg_session_start Start a working session

Sessions drive decay scoring. Start one per work block; nodes decay between sessions.

Parameters

project?: string
create_project?: boolean
notes?: string

Example

kg_session_start({
  project: "api-redesign"
})
kg_session_info Current session details

Read-only. Returns the current session and node counts by type.

Parameters

(no parameters)

Example

kg_session_info({})
kg_session_end End the current session

Ends the active session. Nodes and edges are kept.

Parameters

(no parameters)

Example

kg_session_end({})
kg_node_create Record knowledge artifacts

Capture observations, decisions, problems, approaches, and more. Generates embeddings for semantic search.

Parameters

type: "observation" | "decision" |
      "problem" | "approach" | ...
content: string
status?: "open" | "resolved" | ...
relates_to?: string[] // node IDs, max 20
project?: string
container?: string
tags?: string[]

Example

kg_node_create({
  type: "decision",
  content: "Use Zod for validation",
  tags: ["architecture"]
})
kg_query Search the knowledge graph

Semantic search with spreading activation. Finds related nodes through learned edges.

Parameters

text?: string  // semantic query
type?: string  // filter by type
status?: string
project?: string
spread?: boolean  // default: true
limit?: number    // default: 10

Example

kg_query({
  text: "authentication flow",
  type: "decision",
  limit: 5
})
kg_node_update Update and reactivate nodes

Modify node status or content. Reactivates the node, preventing decay.

Parameters

id: string      // node ID
status?: string // new status
content?: string // regenerates embedding

Example

kg_node_update({
  id: "node:abc123",
  status: "resolved"
})
kg_relate Create explicit relationships

Create or reinforce edges between nodes. Strengthens spreading activation paths.

Parameters

from: string  // source node ID
to: string    // target node ID

Example

kg_relate({
  from: "node:abc",
  to: "node:xyz"
})
kg_status Get current session state

Overview of session, open problems/todos, and recent decisions.

Parameters

project?: string  // filter by project

Returns

current_session: number
total_nodes: number
open_todos: Node[]
open_problems: Node[]
recent_decisions: Node[]
recent_approaches: Node[]
kg_meta_model Read a stored meta-model

Read-only. Returns the stored meta-model of a container, project or person through a methodology, resiliency or process lens. Models are computed ahead of time (nightly on the hosted service), not on request. A scope with no stored model yet returns status "not_computed". On the hosted service the meta-model is part of the paid plans; the methodology lens is limited to the business plans.

Parameters

scope: "container" | "project" | "person"
id?: string  // required for project (name) and person (email)
lens?: "methodology" | "resiliency" | "process"  // default: methodology

Example

kg_meta_model({
  scope: "project",
  id: "api-redesign",
  lens: "process"
})

Concepts

Sessions

Start a session per work block. Decay happens between sessions, surfacing recently active knowledge.

Decay

Old nodes fade over time. Use kg_node_update or kg_query to reactivate what matters.

What changes

Only kg_node_update edits node content. Queries, relates and session starts update usage metrics (decay and activation scores) that weight future results.

Spreading Activation

Queries activate connected nodes through learned edges. Related knowledge surfaces automatically.

Troubleshooting

Opening the URL in a browser shows 405
That is expected. The endpoint speaks MCP over POST. Add it in an MCP client instead.
The client reports 401
Complete the sign-in. If it persists, remove the connector and add it again.
Queries return nothing
New accounts start empty. Results appear after your AI has captured something.
